The query path, step by step

  1. 1A panel or Explore runs a query. DataSourceWithBackend in @grafana/runtime sends POST /api/ds/query with the queries and time range.
  2. 2Middleware authenticates the caller (session, API key, service account token, OAuth, JWT) and builds the request context. RBAC checks datasources:query.
  3. 3The handler in pkg/api/ds_query.go decodes the request and calls the query service.
  4. 4The query service resolves each data source, groups queries by data source, and runs the groups concurrently.
  5. 5When the request contains expressions (__expr__), the server-side expression engine builds a dependency graph and runs math, reduce, resample, threshold, and SQL nodes over the results.
  6. 6The plugin client runs a middleware chain (auth headers, caching, tracing, metrics, logging) and calls QueryData.
  7. 7Core data sources in pkg/tsdb answer in-process. External backend plugins receive the call over gRPC.
  8. 8The plugin queries the external system in its native protocol. Data frames flow back the same way to the browser, which renders them in the panel.

Also worth knowing

  • Alerting: the ngalert scheduler evaluates rules on an interval through pkg/expr and the plugin client, tracks alert state, and hands firing alerts to an embedded Alertmanager for routing and notification.
  • Grafana Live: a Centrifuge-based WebSocket hub at /api/live/ws streams data from plugins (RunStream), dashboard events, and pushed metrics.
  • Two API styles: classic REST handlers under /api/* and Kubernetes-style resources under /apis/*, served by the app platform API server and backed by unified storage.
  • Provisioning: YAML files under conf/provisioning create data sources, dashboards, plugins, and alerting resources at startup.
